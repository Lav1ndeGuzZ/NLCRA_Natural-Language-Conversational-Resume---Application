## 2. 一句话方案

> 用户打开网页 → 粘贴猎聘 token（只存浏览器 sessionStorage）→ DeepSeek 通过多轮对话整理经历、生成简历、导入/补充猎聘在线简历 → 搜索猎聘职位 → 用户确认后真实投递 → 3/7/14 天提醒手动回填状态 → 反馈调权。服务端只做无状态代理，不存 token/简历；DeepSeek Key 由部署环境配置，用户无感。

## 3. 关键决策

| 决策 | 结论 | 影响 |
| --- | --- | --- |
| 市场 | 中国 | 合规、简历格式、平台合作 |
| 形态 | **无登录 Web 工具** | 无账号/租户/权限；用共享访问码+限流防滥用 |
| 部署 | Docker 到独立主机 | Caddy + FastAPI；一台 2C4G 主机可跑 |
| 平台 | **只接猎聘** | 单平台做深；其他平台不接 |
| 猎聘认证 | 用户粘贴 `x-user-token` | 存 sessionStorage；90 天有效；服务端不落库 |
| LLM | DeepSeek，服务端 Key | 部署时 `.env` 配置一次，用户无需填写 |
| 数据 | 浏览器 IndexedDB | 简历/投递/状态本地；服务端无用户 DB |
| 状态 | 猎聘暂无状态 API | 手动回填 + 提醒 + 消息粘贴；等官方开放 |
| 前端 | React 19 + Ant Design 5 + Vite | 对话/编辑器/时间线 |
| 后端 | Python 3.12 + FastAPI | 代理猎聘/DeepSeek、PDF/DOCX |

## 4. 猎聘接入的 5 个硬事实

1. **不是标准 MCP Server**：官方是“CLI + REST”，路径 `/mcp/*` 只是命名；实际用 `x-user-token` 调 REST。
2. **Token 90 天、60 次/分钟**：搜索/查看/改简历/投递共用配额。
3. **没有状态查询**：官方 FAQ 明确“后续版本支持”；HR 回复走猎聘 App/短信。
4. **没有职位详情接口**：只有 `search-job` 和 `apply-job`；搜索结果是否含 JD 全文需真实 token 验证。
5. **简历只补不改**：官方说明 Agent 只补缺失字段，不覆盖已有内容；我们也必须 diff + 确认。
